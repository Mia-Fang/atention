# Dark Pattern Auditing Bureau / 暗黑模式审计局

一个面向工程心理学课程作业的交互式注意实验网站。被试扮演高级 UX 体验官，完成视觉搜索与 UI 反应冲突两项任务，并可选用 WebGazer 进行浏览器端眼动估计。

## 功能

- 被试编号登记、知情同意与设备检查
- 眼动摄像头权限、9 点校准、5 点验证（平均验证误差阈值 180 px）
- 实验一：2（干扰项数量：4/12）× 2（拒绝目标显著性：低/高），每条件 10 次，共 40 次
- 实验二：2（颜色—文字相容性）× 2（后果提示：无/有），每条件 10 次，共 40 次
- 记录反应时、首次点击正确率、错误点击、条件、注视样本与验证质量
- 个人描述性报告、CSV/JSON 下载、课程平台上传
- 无眼动模式下仍可完成行为实验；报告会明确标记眼动不可用

## 本地运行

1. 解压项目。
2. 使用 Chrome 或 Edge 打开 `index.html`。
3. 推荐通过 GitHub Pages 运行，以获得 HTTPS 摄像头权限。浏览器对 `file://` 的摄像头权限行为因浏览器设置而异。
4. 在首页填写匿名被试编号，阅读并勾选同意。

## GitHub Pages 部署

1. 新建一个 **Public** GitHub repository。
2. 上传 `index.html`、`styles.css`、`app.js`、`README.md`。
3. 打开仓库 Settings → Pages。
4. 在 Build and deployment 中选择 Deploy from a branch。
5. Branch 选择 `main`，目录选择 `/ (root)`，保存。
6. 等待部署完成，访问 GitHub Pages 提供的 HTTPS 地址。
7. 将该链接放入课程提交材料。

## 眼动方法与解释限制

- WebGazer 在浏览器端使用摄像头估计屏幕 gaze 坐标。
- 9 点校准：每个位置点击 5 次，共 45 次校准点击。
- 5 点验证：计算每个验证点附近采样预测的平均坐标误差；平均误差 ≤ 180 px 标记为通过。该阈值是课程项目的工程质量门槛，不是眼动仪临床/实验室标准。
- 正式试次记录估计坐标样本，并在刺激消失前按目标按钮矩形 AOI 与竞争按钮 AOI 计算样本比例、任务区域比例及首次目标 AOI 样本潜伏期。
- 目前的任务区域比例是粗略屏幕区域指标，不等于基于精确 AOI 边界的注视时长，也不应被解释为认知加工的直接证据。
- 摄像头视频不上传、不保存。只将任务相关 gaze 坐标样本随实验数据提交；参与者须事先同意。

## 数据分析建议

### 实验一：视觉搜索

- 描述各条件平均正确 RT、首次点击正确率、错误点击比例。
- 估计干扰项数量效应：多干扰平均 RT − 少干扰平均 RT。
- 估计显著性效应：高显著平均 RT − 低显著平均 RT。
- 估计交互作用：比较显著性效应在多干扰和少干扰条件下的差异。
- 搜索斜率可用两个干扰项水平的均值差除以干扰项数量差（12−4）；由于只有两个数量水平，应将其称为本项目的两点斜率估计，而非完整经典搜索函数。

### 实验二：UI 反应冲突

- 冲突成本 = 不相容 RT − 相容 RT。
- 分别计算无提示、有提示条件下的冲突成本。
- 冲突缓解量 = 无提示冲突成本 − 有提示冲突成本。
- 同时分析首次点击错误率，避免只看 RT。
- 颜色—文字不一致属于 UI 反应冲突 / S-R 不相容变体，不是经典颜色词 Stroop 的直接复现。

### 眼动分析

- 首先报告校准/验证状态、验证平均误差和有效试次覆盖率。
- 分实验、分条件比较有效 gaze sample 数、屏幕内样本比例、任务区域样本比例。
- 实验一比较拒绝目标 AOI 与诱导按钮 AOI 的样本比例，并按干扰项数量、显著性条件分层；实验二比较正确按钮与竞争按钮 AOI 样本比例，并按相容性和提示条件分层。当前指标是 gaze sample proportion，不是 fixation dwell time；需要进一步实现 I-VT/I-DT 等注视识别算法才能报告 fixation duration。
- WebGazer 数据是粗略估计，需谨慎解释，不能声称达到实验室眼动仪精度。

## 重要限制与提交前检查

- 本项目当前上传代码使用课程提供的 POST URL 和 `{project, experiment, participant, condition, trials}` 结构；必须在正式招募前用测试编号跑一次并在老师后台确认数据确实入库。
- `GET /api/hw2/data` 的鉴权方式和下载密钥未放进前端。不要将私密密钥提交到 GitHub。
- 需要真实参与者数据才能计算群体效应量、置信区间或与全班数据比较。个人报告只显示个人描述性表现。
- 正式收数前请用至少 2–3 台不同电脑预试，检查摄像头权限、校准、验证、左右按钮平衡、试次数量、导出和上传。
